# Assignment 2: Predicting GitHub User Activity

This project predicts whether each test user will open a pull request, open an issue, comment on an issue, submit a PR review, comment on a PR diff, or push commits during the following week. Each user receives six independent binary predictions.

The reproduction steps below cover data download and preprocessing, feature construction, training, historical evaluation, and generation of `output_314561001.csv`.

## Data Source

The data used in this assignment is sourced from [GH Archive](https://www.gharchive.org/), a public archive of GitHub events. This project uses the eight anonymized tables generated by the course-provided [preprocessing script](official/scripts/preprocess.py). See the [official schema](official/SCHEMA.md) and the [course repository revision](official/COMMIT.txt).

## 2. Download and preprocess historical data

Use the original course-preprocessed Parquet archives when reproducing reported metrics. Place `train_db.zip`, `valid_db.zip`, and `test_db.zip` in `data_inputs/`. The CLI also accepts directories containing the eight Parquet files. Supply sources in chronological order in either case.

```bash
DEVICE=cuda:0
HIST_DB=(data_inputs/train_db.zip data_inputs/valid_db.zip data_inputs/test_db.zip)
```

To rebuild the historical inputs from raw GH Archive files, request the three ranges below. Downloader timestamps are **UTC** and `--end` is exclusive. Keep each download manifest as a record of the hours used. If a download reports errors, review its manifest before preprocessing and record any unavailable hours. The original experiment metadata records Parquet hashes. The hour-by-hour download manifests for the historical runs are unavailable in this checkout.

```bash
python download.py --start 2025-12-01T00 --end 2026-07-02T00 \
  --out raw/train --manifest data/train_hours.json
python download.py --start 2026-07-02T00 --end 2026-10-01T00 \
  --out raw/validation --manifest data/validation_hours.json
python download.py --start 2026-10-01T00 --end 2026-11-14T16 \
  --out raw/test --manifest data/test_hours.json

for split in train validation test; do
  python official/scripts/preprocess.py --raw "raw/$split" --out "data/$split"
done

HIST_DB=(data/train/db data/validation/db data/test/db)
```

Each source is preprocessed separately. The loader resolves foreign keys within their source, maps rows to stable anonymized IDs, and deduplicates events across sources. Archive names refer to the source partitions. The cutoffs in the next section determine which examples are used for training and evaluation.

## 3. Build features and train

Both reported runs use the 9,000-user course cohort, a **21-day input window**, a **7-day label window**, and up to eight graph neighbors per route. Both plans bound the underlying observations from December 1, 2025 at 08:00 to November 15, 2026 at 00:00 (exclusive), Taiwan time.

| Split | Cutoffs in 2026, 00:00 Taiwan time | Purpose |
|---|---|---|
| Train, 14-week run | Apr 1 to Jul 1, every 7 days | Fit weights and input statistics |
| Train, 29-week run | Jan 1 to Jul 16, every 7 days | Fit weights and input statistics |
| Early stopping | Aug 2 and 9 | Select the epoch by binary cross-entropy |
| Calibration | Aug 16 and 23 | Fit one decision threshold per activity |
| Validation | Sep 6, 13, and 20 | Compare models on 27,000 user-weeks |
| Historical test | Oct 4, 11, 18, 25, Nov 1, and 8 | Report scores on 54,000 user-weeks |

At cutoff `t`, features use events in `[t − 21 days, t)` whose rows were also available before `t`. An older parent issue or PR may serve as a join endpoint if it was already known. Labels use activity in `[t, t + 7 days)` observed before the label window closes. The model leaves out late close and merge fields. The reported runs used no hourly coverage manifest. An empty observation window can reflect missing archive data.

| Model | Inputs and prediction rule |
|---|---|
| `copy7` | Repeat the six binary activity flags observed in the previous seven days |
| `base` | MLP on the user's six recent activity counts |
| `graph` | Base plus a graph branch that pools neighbors within each of 12 typed routes, then pools across routes |
| `temporal` | Base plus a causal encoder of daily features, with pooling across 1, 3, 7, 14, and 21 days |
| `additive` | Add the Graph and Temporal corrections to the Base logits |
| `adaptive` | Apply per-label gates to the branch corrections and their interaction |

Trainable models use AdamW with learning rate `0.0005`, weighted binary cross-entropy, batch size `256`, up to `16` epochs, patience `4`, hidden size `32`, and seed `42`. Adaptive uses branch dropout of `0.1`. Copy7 has no fitted weights. The shared CLI also implements `gnn_time` as an optional comparator.

### Run the 14-week experiment

```bash
bash scripts/run_historical.sh runs/full_repro "$DEVICE" "${HIST_DB[@]}"
```

The script runs EDA, renders the schema, prepares the cutoff snapshots, trains the six models above, and evaluates validation and historical test. `runs/full_repro` must be a new directory. The checked-in plan is [`configs/historical.json`](configs/historical.json).

### Run the 29-week experiment

Create a copy of the plan with the original 29-week training bounds. The last bound, July 19, produces a final weekly cutoff on July 16.

```bash
mkdir -p runs/plans
python - <<'PY'
import json
from pathlib import Path

plan = json.loads(Path("configs/historical.json").read_text())
plan["train"].update(
    first="2026-01-01T00:00:00+08:00",
    last="2026-07-19T00:00:00+08:00",
)
Path("runs/plans/historical_29w.json").write_text(json.dumps(plan, indent=2) + "\n")
PY

RUN=runs/no_gnn_repro
python run_adaptive.py prepare \
  --db "${HIST_DB[@]}" --plan runs/plans/historical_29w.json --data "$RUN/data"
python run_adaptive.py train \
  --data "$RUN/data" --out "$RUN/models" --device "$DEVICE" \
  --models copy7 base graph temporal additive adaptive
python run_adaptive.py evaluate \
  --data "$RUN/data" --models "$RUN/models" --device "$DEVICE" \
  --split evaluation --out "$RUN/validation"
python run_adaptive.py evaluate \
  --data "$RUN/data" --models "$RUN/models" --device "$DEVICE" \
  --split test --out "$RUN/test"
```

Use the same `prepare → train → evaluate` commands with `--plan configs/historical.json` and a fresh `RUN` to run the 14-week experiment without EDA or Graphviz. To train an individual variant, pass its name to `train --models` and use a fresh model output directory. For `evaluate`, `--models` takes the path to that directory. Changing the time plan requires new snapshots and checkpoints.

## 4. Read the historical results

The score is `(macro-F1 + micro-F1) / 2`, pooled across the user-weeks in each split. These are the scores recorded in the two provided runs.

| Model | 14-week validation | 14-week test | 29-week validation | 29-week test |
|---|---:|---:|---:|---:|
| Copy7 | **0.4945** | 0.4264 | 0.4945 | 0.4264 |
| Base | 0.4504 | 0.4464 | 0.4671 | 0.4439 |
| Graph | 0.4701 | 0.4479 | 0.4907 | **0.4599** |
| Temporal | 0.4879 | 0.4513 | 0.4913 | 0.4539 |
| Additive | 0.4817 | **0.4544** | **0.5048** | 0.4549 |
| Adaptive | 0.4751 | 0.4499 | 0.4614 | 0.4510 |

Use `summary.csv` for pooled scores, `weekly.csv` for week-by-week scores, and `per_label.csv` for the six activity breakdowns. The `models/<model>/run.json` records model settings, source hashes, calibration thresholds, and the selected epoch. The historical scores cover October 4 to November 15, 2026 and serve as reference measurements for the official forecast.

## 5. Generate the official prediction file

The submission target is **November 22, 2026 00:00 to November 29, 2026 00:00, Taiwan time**. For a checkpoint trained with 21 days of history, the feature window starts on November 1 at 00:00 Taiwan time. Append a preprocessed source for the available hours after the historical archives end. Preserve the original order of the earlier sources.

```bash
python download.py --start 2026-11-14T16 --end 2026-11-21T16 \
  --out raw/submission_history --manifest data/submission_hours.json
python official/scripts/preprocess.py \
  --raw raw/submission_history --out data/submission_history
```

Use the latest course test user list. The bundled `official/submission/test_input.csv` contains 4,465 users. Set `CHECKPOINT` to the actual checkpoint selected for submission. The example below uses Additive from the 29-week run because it had the highest recorded validation score.

```bash
CHECKPOINT=runs/full/models/additive/model.pt
TEST_USERS=official/submission/test_input.csv
PREDICTION=outputs/output_314561001.csv

python run_adaptive.py predict \
  --checkpoint "$CHECKPOINT" \
  --db "${HIST_DB[@]}" data/submission_history/db \
  --users "$TEST_USERS" --cutoff 2026-11-22T00:00:00+08:00 \
  --out "$PREDICTION" --device "$DEVICE"

python official/scripts/evaluate.py --pred "$PREDICTION" --input "$TEST_USERS"
```

The CSV contains one row per test user, with integer `0` or `1` for each activity and this exact header:

```csv
UserID,open_pr,open_issue,issue_comment,pr_review,pr_review_comment,push
```

Keep the generated `output_314561001.csv.metadata.json` with the checkpoint and data manifests. It records the exact checkpoint, test list and source hashes, cutoff, batch size, and six thresholds needed to reproduce the output. Submit the CSV to E3. The format check validates the CSV against the test user list.
